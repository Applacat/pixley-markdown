Ralph Mission: Renderer Identity + Scroll Restoration (#81, #84)
================================================================

Design decisions:
- MarkdownBlock/parser MOVED to the aimdRenderer package (public API) so
  identity tests run against the real parser — same precedent as
  ElementRelocator. App-target file deleted; consumers unchanged (all three
  already imported aimdRenderer).
- Block identity: id is String = kind signature (short content hash, stable
  within a process run) + ordinal among same-signature blocks. Invariant
  under insertion/removal elsewhere; only identical-content duplicates
  re-ordinal. Interactive element signatures deliberately EXCLUDE mutable
  state where the anchor is stable (checkbox label not checked-state,
  choice/review option lists not selection) so toggling keeps identity.
- ListItemBlock.id: item text hash + ordinal (was UUID-per-parse).
- Control state refresh at unchanged identity: onChange added to
  FillInTextField (element.value), FeedbackTextEditor (existingText),
  ReviewControlView (options.isSelected map, with a guard so the external
  sync never resubmits an already-selected option). Exempt by design:
  FillInDatePicker (value change changes hint → identity changes → fresh
  init; onChange would loop through its auto-submit), slider/stepper/toggle/
  color (markers consumed on any write → block kind changes anyway).
- Scroll restore: NativeDocumentView gains restoreScrollProgress (fed from
  MarkdownView.pendingScrollPosition, same source as Plain mode). First
  parse maps progress → block index → scrollTo(stable id). Subsequent
  reparses capture the topmost visible block id before the swap and scroll
  back to it (exact, thanks to stable ids). MarkdownView applies
  .id(selectedFile) to the renderer so per-document view state (didRestore,
  search, cache) resets on file switch.
