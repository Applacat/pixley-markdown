Write-Back Integrity — #77 (stale ranges), #80 (unserialized writes), #90 (AI routing)
======================================================================================

Design decisions:
- Serialization: per-URL write chains keyed by url.path (static registry on
  @MainActor InteractionHandler → multi-window + chat writes to the same doc
  serialize). Each write awaits the previous chain entry.
- Re-detection: ElementRelocator (aimdRenderer package, pure + unit-testable)
  re-locates every element in freshly-read content before replacing.
  Matching: ORDINAL among same-signature candidates when counts match
  (shift-invariant — survives large upstream insertions), else nearest
  offset. Signatures per type (label+state, hint+type, state list, etc.).
  Free-text anchors: selection (Add Comment) and line text (gutter) use the
  same ordinal-first strategy.
- On relocation failure: WriteError.rangeMismatch → existing error banner
  ("Document changed externally. Please try again."). Never writes blind.
- AI routing: ChatTools emits typed ElementEdit (element + intent) instead of
  raw ranges; ChatView routes through InteractionHandler with the tool's
  content snapshot as the relocation anchor and coordinator.activeFileWatcher
  for suppression. The parallel write path in ChatView is gone.
- Gutter comments moved from MarkdownView's inline offset arithmetic into
  InteractionHandler.setGutterComment (line-anchor relocation + array-based
  line editing — the old Character/joined() offset math is gone).
- apply(edit:)/InteractiveEdit raw-range write path removed from live code.
  The InteractiveEdit enum remains only for dead SelfDescribingElement
  (#90 format-divergence work, still open).
